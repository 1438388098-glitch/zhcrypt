# zhcrypt 安装包全面审计与优化报告

审计对象：`D:\APP\zhcrypt`（88.14 MB，2058 个文件，PyInstaller onedir × 3 + Inno Setup 安装产物）
审计时间：2026-08-01
审计方法：5 个并行子代理分层层级审计 + 本地侦察交叉验证。全部发现基于二进制取证（PE 解析、PyInstaller CArchive/PYZ 反解、字节码反汇编、哈希比对、NVD/OSV/GitHub Advisory 在线核实），未修改目标目录任何文件。

---

## 一、总体结论

**这是一个"2018 年代工具链、2026 年构建、三层重复部署"的加密通信应用安装包**，安全性与工程质量存在系统性缺陷：

1. **致命**：全部 TLS 通信跑在 Python 3.6.5（2018-03，EOL 2021-12）+ OpenSSL 1.0.2k（2017-01，EOL 2019-12）之上，15+ 个已公开 CVE 未修复，无 TLS 1.3。
2. **致命**：整个发布物不可复现、不可审计、不可更新（无源码对应、无 .spec、无锁定依赖、无 SBOM、无版本一致性、无更新机制）。
3. **高**：43.12 MB（48.9%）纯冗余；三个 EXE 功能集不一致且 root "完整版"缺失 certpin/secretsharing 模块（安全功能必然崩溃）；所有 EXE/pyd 无数字签名；文档层死链。
4. **良性面**：加密原语层健康（argon2-cffi 21.3.0 / cryptography 40.0.2 Rust 后端内嵌 OpenSSL 3.1.0 / bcrypt 4.0.1 / websocket-client 1.3.1，均为 2022-2023 版本）；证书验证三层齐全（系统 CA + 主机名校验 + SPKI 钉扎 TOFU）；未发现硬编码密钥/凭据；组件完整性（RECORD 校验 23/23、三副本哈希一致）无篡改迹象。

## 二、发现总览（按层级）

严重级别：**致命** > 高 > 中 > 低 > 建议。编号 ZC-01 起，贯穿全文。

### L1 可执行文件层（4 个 EXE）

## 四、修复路线图

### P0 — 立即（安全止损，1 周内）
1. **整体重建，升 Python**：用 Python 3.12/3.13（本机已有 3.13）重建。一步解决 ZC-09（_ssl 内嵌 OpenSSL 3.0.x）、ZC-10、ZC-15、ZC-26。
2. **目标依赖组合**（PyPI 元数据已核实）：cryptography 49.x/50.0.0（≥3.9，纯 Rust 后端）、argon2-cffi 25.1.0（≥3.8，Argon2id v19 格式跨版本兼容，存量数据无需迁移）、cffi 2.x、bcrypt 5.0.0（或剔除）、websocket-client 最新、PyInstaller 6.x/7.x + 最新 hooks-contrib（含 cryptography `_rust.pyd` 拷贝 hook）。
3. **修复 hiddenimports 缺陷**（ZC-02）：spec 中 `hiddenimports=['certpin','secretsharing']`；`excludes=['setuptools','pkg_resources','wheel','bcrypt'(可选),'ctypes','multiprocessing','distutils','decimal','xml']`。
4. **回归清单**：RSA-4096-OAEP-SHA512、AES-256-GCM、Ed25519/X25519、X3DH、双棘轮、certpin 钉扎、websocket TLS 握手、Argon2id verify 兼容性。

### P1 — 短期（2-4 周）
5. **消除 43 MB 冗余**（ZC-29）：单一运行时目录 + 两个入口（GUI/CLI 共享依赖），88 MB → ~45 MB；删除 root 旧 build（无 spec 来源）。

7. **清理死重**（ZC-11/12/13/20/24）：裁掉 win32com/MFC 链（8.19 MB，删除后全功能回归）、裁剪 base_library.zip encodings（~378KB，或用 3.12 重建自然消失）、删 pyexpat/_decimal/_ctypes 等不可达扩展。
8. **代码签名**（ZC-01/25）：OV/EV 证书签名 3 个 EXE + 卸载器 + 安装器 + 关键 pyd；发布 SHA-256 校验清单。加固安装目录 ACL（仅 SYSTEM+Administrators）。

## 八、动态测试（补充审计 #1）—— 发现并修复 3 个真实缺陷

在本地起真实服务器（Flask 5000 + websockets 5003），双客户端 alice↔bob 全流程 22 项断言全部通过：
X3DH 握手 / x3dh_reply / 双向棘轮消息 / Ed25519 消息验签 / 会话持久化（重启）/ REST 降级轮询 /
2MB 文件上传下载解密一致 / 阅后即焚（二次下载无数据）/ 安全码一致 / 篡改签名拒绝。

动态测试发现并已修复：
1. **【高危·DoS/性能】one-time prekey 加载 = 50 次 Argon2id(256MB) 串行派生**：首次收到 x3dh_init 需 ~45-90 秒才能解密，且可被恶意 init 消息当作 CPU/内存 DoS。修复：`generate_prekey_bundle` 单一 salt 派生包密钥 + `load_otp_private_keys` 按 salt 去重（源码级）。
2. **【高危·协议】x3dh_init 消息的 `signing_public_key` 字段误放接收方公钥**：导致响应方 TOFU 固定了错误公钥、安全识别码两端不一致。修复：发送方签名公钥 + 响应方缓存发送方静态公钥（源码级）。
3. **【低】websockets 17 `ConnectionClosed` 构造签名变更**：测试基建适配（旧 `(code,reason)` → 新 `(rcvd,sent)`）。

另验证：冻结版 exe 交互路径因控制台 getpass 无法自动驱动（环境限制，非缺陷），密码类流程经同一代码的自动化测试覆盖。
